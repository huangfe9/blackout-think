## budget.py: client-side hard spend cap

The Meta Model API only offers email alerts, so this is the only hard limit. Anything that cannot be priced must be refused, not let through.

Names:
- `STOP_AT_USD = 140.0`; `LEDGER_FILE = Path(__file__).parent / ".muse_spend.jsonl"`
- `METERED_PATHS = ("/v1/responses", "/v1/chat/completions")`; `TRANSCRIBE_PATH = "/v1/asr/transcribe"`; `TRANSCRIBE_MODEL = "muse-voice-transcribe-1.0"`; `TRANSCRIBE_USD_PER_HOUR = 0.18`; `TRANSCRIBE_WORST_CASE_USD = 0.03` (the API rejects audio over 10 minutes)
- `Price(NamedTuple)` with `input`, `cached_input`, `output` in USD per 1M tokens, and `PRICES: dict[str, Price]`:
  - `muse-wonder-1.0`: 4.00, 0.20, 20.00
  - `muse-spark-1.3`, `muse-spark-1.2`, `muse-spark-1.1`: 1.25, 0.15, 4.25
  - `muse-spark-1.3-contributor`, `muse-spark-1.2-contributor`: 0.10, 0.002, 0.20
- `spent_usd(ledger: Path = LEDGER_FILE) -> float`: sum of the JSONL ledger; 0.0 if the file is missing
- `record_spend(ledger: Path, model: str, usd: float) -> None`: append one line `{"model": ..., "usd": ...}`; appends only, so concurrent processes cannot overwrite totals
- `max_output_tokens(body: dict) -> int | None`: first truthy value of `max_output_tokens`, `max_completion_tokens`, `max_tokens`
- `refusal_reason(path: str, body: dict) -> str | None`, in this order, with these exact messages:
  - path not metered: `f"{path} has no price rule in budget.py"`
  - model not priced: `f"model {model!r} has no price in budget.py"`
  - `stream` or `background` truthy: `"streaming and background calls cannot be metered"`
  - any tool whose `type` contains `search`: `"built-in search tools are billed per query and cannot be metered"`
  - no max output value: `"set max_output_tokens so the worst-case cost is known"`
- `worst_case_usd(body: dict, request_bytes: int) -> float`: treat every 2 request bytes as one input token at the input price, plus the max output tokens at the output price
- `actual_usd(model: str, usage: dict) -> float`: accepts Responses fields (`input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`) and Chat Completions fields (`prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens`). Cached tokens are billed at the cached rate and not again at the input rate. Reasoning tokens are already inside output tokens. A missing token count must raise `KeyError`.
- `refusal_response(request: httpx.Request, message: str) -> httpx.Response`: status 402, JSON `{"error": {"code": "local_budget_guard", "message": f"Blocked locally: {message}"}}`, with `request=request`
- `class BudgetedHttpClient(openai.DefaultHttpxClient)` with `__init__(self, *, ledger: Path = LEDGER_FILE, limit_usd: float = STOP_AT_USD, **kwargs)` and an overridden `send(self, request, **kwargs)`.
- Running `python budget.py` prints `Spent $X.XXXX of the $140.00 limit`.

`send` behaviour:
- GET passes through uncharged.
- `TRANSCRIBE_PATH`: refuse if spent plus the worst case exceeds the limit, with a message containing the word `limit`. On success record `audioDurationMs / 3_600_000 * 0.18`; if that is unreadable, record the worst case.
- Every other method: the body must parse as JSON or it is refused with a message saying it cannot be priced. Apply `refusal_reason`. Refuse with a message containing the word `limit` if spent plus the worst case exceeds the limit. Send only after those checks. Read the response body. On success record `actual_usd`; if usage is missing or unreadable, record the worst case. A failed response records nothing.

Two constraints that must not be designed around:
- Refuse by returning the 402 response. Do not raise from `send`: the OpenAI SDK retries exceptions raised there and reports them as connection errors.
- Override `send` on a `DefaultHttpxClient` subclass. Do not pass a custom transport internally: httpx ignores environment proxies when a transport is set, and users may depend on a proxy.
